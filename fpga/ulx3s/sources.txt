# sources.txt — the ULX3S prototype source list, in elaboration order.
#
# ONE list, read by BOTH builders:
#   fpga/ulx3s/synth.ps1                  (Windows, local, synth-only)
#   .github/workflows/fpga-ulx3s.yaml     (Linux, CI, full bitstream)
# Keeping it in one file is the point: a source added to only one of the two
# builders is a drift bug that shows up as "works locally, fails in CI" - or
# worse, the reverse, CI green on a design that is not the one you flash.
#
# The chip sources below are info.yaml's `source_files`, in the same order,
# PLUS the FPGA-only blocks listed under their own heading. If info.yaml gains
# a file and this list does not, the two designs have quietly diverged.
#
# The FPGA-only exceptions are deliberate and are both about resources a
# TinyTapeout tile does not have: `sdram_ctrl.sv` needs the board's soldered
# SDRAM, and `icache.sv` needs block RAM. Both are behind `` in
# project.sv, so the ASIC source set still elaborates on its own. (This comment
# used to claim the two lists were identical; sdram_ctrl.sv had already made
# that false, and icache.sv is the second exception.)
#
# `font_rom.svh` is NOT listed: it is an include, pulled in by vga_text.sv.
# Both builders pass `-I src` so the relative include resolves regardless of
# the working directory - the old README's hand-typed yosys line did not, and
# that was a real trap.
#
# Blank lines and #-comments are ignored by both readers.

# microSD, and the vendored engine it wraps. FPGA-only for the same reason: a
# TinyTapeout tile has no pin for a card. vendor/ files are verbatim copies from
# console and must not be edited here - see vendor/README.md.
vendor/spi_master.sv
vendor/sd_spi.sv
src/sd_ctrl.sv

# GPDI/HDMI, koti's standard video output (user directive 2026-08-07). Vendored
# VERBATIM from console, which drove this exact board's HDMI on 2026-08-06.
# tmds_encoder must precede dvi_tx, which instantiates it. pll_25_125 is an
# ecppll-generated EHXPLLL wrapper and is harness-only, like ulx3s_top.
vendor/tmds_encoder.sv
vendor/dvi_tx.sv
vendor/pll_25_125.v

# USB HID keyboard (US2). The core is vendored; src/usb_hid_host_rom.v is KOTI'S
# — upstream's ROM wrapper uses a relative $readmemh path that cannot resolve
# from both the repo root and test/, and fails SILENTLY. See tools/mkusbrom.py.
# vendor/usb_clock.v declares a module called `clock` (generic, but verbatim).
vendor/usb_clock.v
src/usb_hid_host_rom.v
vendor/usb_hid_host.v
src/usb_kbd.sv

# Sound: the onboard 3.5 mm jack's 4-bit R2R ladder. vendor/audio.sv is
# console's chiptune synth, copied verbatim; src/audio_r2r.sv is koti's own,
# and is the part that spends four bits well instead of throwing four away.
vendor/audio.sv
src/audio_r2r.sv

# ---- harness only: no silicon pin exists for any of this ----
fpga/ulx3s/ulx3s_top.sv
